## 0. Infrastructure & Cluster Join Fix

The worker nodes likely failed to join automatically due to a **timing race condition**. The `worker.sh` script tries to download the join command from S3 immediately upon boot. If the Master node hasn't finished installing Kubernetes and uploading the token to S3 by then, the download fails, and the worker gives up.

### Fix: Manually Join Workers
1.  **Get Master Public IP & Key:**
    ```bash
    terraform output
    # Note the Master Public IP and key location
    ```

2.  **Get Join Command from Master:**
    ```bash
    ssh -i k8s-key ubuntu@<MASTER_PUBLIC_IP> "cat /home/ubuntu/join-command.sh"
    # Copy the output (starting with 'kubeadm join ...')
    ```

3.  **SSH into EACH Worker and Join:**
    *(Get worker IPs from AWS Console or `terraform state show`)*
    ```bash
    ssh -i k8s-key ubuntu@<WORKER_PUBLIC_IP> "sudo <PASTE_KUBEADM_JOIN_COMMAND>"
    ```

4.  **Verify Cluster on Master:**
    ```bash
    ssh -i k8s-key ubuntu@<MASTER_PUBLIC_IP> "kubectl get nodes"
    ```

## Part 1: Node Labeling & Taints

Replace `<WORKER_NODE_1_NAME>` (e.g., `ip-10-0-102-148`) and `<WORKER_NODE_2_NAME>` with your actual node names found in `kubectl get nodes`.

```bash
# Label Nodes
ssh -i k8s-key ubuntu@<MASTER_PUBLIC_IP> "kubectl label nodes <WORKER_NODE_1_NAME> environment=production storage=ssd tier=frontend"
ssh -i k8s-key ubuntu@<MASTER_PUBLIC_IP> "kubectl label nodes <WORKER_NODE_2_NAME> environment=production storage=hdd tier=backend"

# Taint Nodes
ssh -i k8s-key ubuntu@<MASTER_PUBLIC_IP> "kubectl taint nodes <WORKER_NODE_1_NAME> workload=frontend:NoSchedule"
ssh -i k8s-key ubuntu@<MASTER_PUBLIC_IP> "kubectl taint nodes <WORKER_NODE_2_NAME> workload=backend:NoSchedule"
```

## Part 6: Static Pods

**Note:** Static pods must be created via SSH on the specific worker node, *not* via kubectl on the master.

```bash
# Copy manifest to Worker Node 1
scp -i k8s-key manifests/monitoring/monitoring-agent.yaml ubuntu@<WORKER_NODE_1_PUBLIC_IP>:/home/ubuntu/

# Move to static pod manifest directory
ssh -i k8s-key ubuntu@<WORKER_NODE_1_PUBLIC_IP> "sudo mkdir -p /etc/kubernetes/manifests && sudo cp /home/ubuntu/monitoring-agent.yaml /etc/kubernetes/manifests/"

# Verify (on Master)
kubectl get pods -n kube-system | grep monitoring
```
